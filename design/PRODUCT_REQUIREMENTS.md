# Resonote Product Requirements

> 状态：现行产品合同
> 更新日期：2026-08-14
> 设计语义：[FOUNDATION.md](./FOUNDATION.md) 与 [COMPONENT_SYSTEM.md](./COMPONENT_SYSTEM.md)
> 适用范围：产品定位、功能范围、关键流程、页面职责与恢复行为

## 1. 文档目的

本文件记录 Resonote 当前有效的产品需求与行为合同。它负责回答：

- Resonote 为谁解决什么问题。
- V1 必须支持哪些任务，明确不支持哪些任务。
- 用户如何进入、完成和恢复关键任务。
- 哪些信息需要成为顶层目的地、页面、全局入口或临时界面。
- 不同窗口、输入方式和系统状态下，产品行为如何保持一致。
- 页面设计需要哪些真实内容、状态与技术约束作为输入。

本文件不提前规定页面视觉布局，不以填满 Design System 为目标，也不因为已有视觉稿或组件稿而反向假定产品需求。

## 2. 工作顺序

```text
产品定位与用户任务
→ V1 范围与优先级
→ 信息架构与关键流程
→ 功能合同、内容与状态
→ 页面清单与自适应策略
→ 低保真页面设计
→ 高保真视觉与交互
→ 从真实页面提炼或修订组件
→ 实现与验证
```

只有本文件达到“可进入页面设计”的条件后，才开始系统性产出产品页面。音乐业务组件应从已确认页面中提炼；现有组件草案可以复用、修改或废弃。

## 3. 当前已确认输入

以下内容是进入页面设计与实现时需要共同遵循的现行输入；具体行为仍以后续产品合同为准：

- 视觉基础已具备 Brand、Semantic Color、Typography、Shape、Spacing、Elevation、Motion 与 Accessibility 规则。
- Core Component 已具备 Button、Icon Button、Text Field、Small Top App Bar 和无状态 Adaptive Navigation Suite。
- Primary Navigation 默认使用 Material `WindowAdaptiveInfo` 在 Navigation Bar / Rail 间切换；目的地集合和选中状态由 App 持有。
- Resonote 五档宽度分类继续服务 Grid、内容限宽与验证；Body `1200dp`、Reading `720dp` 是可由页面消费的 Layout Token。
- 主 App 已组合真实 Feature、全局导航、播放 Shell 与持久化主题；Catalog 继续作为独立设计系统检查入口。

## 4. 决策原则

1. 用户任务先于页面，页面先于组件。
2. V1 优先形成一条完整、可恢复、可验证的核心体验，不以功能数量衡量完整度。
3. V1 以 Compact 竖屏手机为正式产品范围，MV 用户显式全屏时的横屏播放是唯一例外；架构与 Design System 继续保持 Adaptive 能力，未来扩展到 Medium/Expanded 时不得静默改变业务语义或丢失状态。
4. Material 3 稳定版默认行为是交互与自适应基线；只有明确产品证据才增加覆盖。
5. 每项功能必须包含 Loading、Empty、Error、Offline、Permission、超长内容等适用状态，不能只描述理想路径。
6. 已有设计系统规则可由真实产品证据修订，但修订必须同步规范、页面和测试。
7. 所有产品界面和业务状态以 Resonote 当前合同、源码与测试为准，并基于 Resonote Design System 和 Android Adaptive 独立演进。

## 5. 产品定位

| 项目 | 已确认结论 |
|---|---|
| 一句话定位 | Resonote 是一款面向大众的无广告沉浸式 Android 音乐应用，统一在线音乐、本地音乐与个人云盘，让用户专注于发现和聆听。 |
| 核心价值 | 无广告、减少与听歌无关的打扰，以沉浸播放、连续后台承接和可控音频共存保持聆听体验。 |
| 目标用户 | 日常使用 Android 听歌的大众用户，同时兼顾拥有本地音乐文件的用户；首版不按年龄或专业程度细分。 |
| 核心场景 | 在线发现并播放、Full Player/歌词与 Queue、后台系统控制、本地导入、登录后音乐库/云盘，以及与其他音频场景协调播放。 |
| 内容来源 | Android 原生 API 在线音乐 + 本地导入音乐 + 个人云盘音乐。 |
| 产品边界 | 完整在线音乐服务与本地播放器的结合；不是社交社区、短视频平台、通用文件下载器或内容创作工具。 |
| 成功标准 | 用可测试的核心任务、状态保持、系统播放承接、账号隔离和零广告打断验收，不依赖产品内行为埋点。 |

当前“沉浸式”至少包含四类可观察合同：不展示广告位、插屏、开屏广告或付费推广打断；
以 Full Player 的封面/歌词作为专注聆听空间；允许用户选择与其他 App 并行播放的音频焦点策略；
播放离开 App 后仍由系统媒体通知承接；Android System UI 可据此自动呈现岛形、状态栏或其他媒体表面。
Full Player 的具体结构、动效和自适应布局仍需在 Player 产品设计阶段冻结。

核心场景优先顺序：

1. 从首页或发现找到音乐并立即播放。
2. 在沉浸式 Full Player 中查看封面、歌词并管理 Queue。
3. 离开 App 后通过通知、锁屏和耳机继续控制。
4. 导入并播放本地音乐。
5. 登录后使用收藏、歌单、历史、云盘与每日 VIP。
6. 按用户选择与游戏、影音或导航播报协调播放。

V1 成功标准：

- 匿名用户可以从在线内容完成发现、播放、Mini Player、Full Player 和后台系统控制闭环。
- 本地文件可以可靠导入，重启 App 后仍保留并可播放。
- 后台播放、标准媒体通知、耳机控制、Queue 和恢复状态符合已确认合同。
- Tab 切换、页面返回及 Android 配置/窗口变化不丢失关键页面和播放状态。
- 登录门禁不自动重放原子操作，不显示旧账号数据，也不泄漏账号授权媒体。
- 全产品不出现广告位、开屏广告、插屏、付费推广或其他与听歌无关的商业打断。

## 7. 信息架构

在功能范围稳定后确认以下内容：

- 顶层目的地及其用户任务，而不是先决定目的地数量。
- 每个顶层目的地的起始页面、空状态和恢复状态。
- Detail、Search、Settings、Player、Queue、Lyrics 等界面属于顶层、二级页面、全局入口还是 Overlay。
- Mini Player、首页搜索入口、Snackbar 等跨页面元素出现和消失的条件。
- Deep Link、系统媒体入口、通知和返回行为如何进入现有 Back Stack。
- 所有窗口是否复用同一目的地集合；任何差异都必须由明确的产品 IA 决策驱动。

信息架构确认表：

| Destination / Entry | 用户目标 | 进入方式 | 离开 / Back | 状态恢复 | 状态 |
|---|---|---|---|---|---|
| 首页 | 快速进入推荐内容并开始听歌 | 默认入口 / Primary Navigation | 根页面 Back 退出 App | Tab 切换、窗口变化与详情返回后保持 | 功能范围与页面合同已确认 |
| 发现 | 主动浏览歌单、榜单、新碟与新歌等在线内容 | Primary Navigation | 根页面 Back 切换首页 | Tab 切换、窗口变化与详情返回后保持 | 功能范围与页面合同已确认 |
| 我的 | 访问个人资料与完整音乐库 | Primary Navigation | 根页面 Back 切换首页 | Tab 切换、窗口变化与详情返回后保持 | 音乐库能力范围与页面合同已确认 |
| 搜索 | 查找在线音乐内容 | 仅首页搜索入口 | 返回首页并保留首页状态 | 保留查询、结果分类与滚动位置 | 独立页面；不在发现或我的重复放置入口 |
| 听歌识曲 | 使用环境声音识别歌曲 | 首页搜索入口右侧话筒 / 搜索页话筒 | 返回来源页并保留查询 | 识别任务结束后保留结果，离开录音阶段即停止采集 | 独立页面；按需请求麦克风权限 |
| Android 文件入口 | 从文件管理器选择打开/分享给 Resonote 并导入音乐文件 | 系统 Intent / 文件选择器 | 导入完成后进入本地音乐上下文 | 复制到 App 目录后不依赖原 URI | 单选、多选、目录、去重与异常合同已确认 |

三个顶层目的地在所有窗口复用，由 Material Adaptive Navigation Suite 在 Bar / Rail 间改变呈现。
当前冻结“首页、发现、我的”的名称、顶层地位和上述职责边界；页面布局、组件、导航层级与功能范围均由 Resonote 当前合同定义。

Resonote 使用 Tabs Shell 加单一全局页面栈，不为每个顶层目的地建立独立详情 Back Stack：

- Navigation Suite 所在的 Tabs Shell 是全局页面栈的起始页面；首页、发现、我的只是 Shell 内三个可切换的根页面，不分别拥有详情 Back Stack。
- 三个根页面在 App 运行期间分别保留列表、滚动、筛选、分页和已加载内容。实现可以使用 Tab 作用域 ViewModel 与 Saved State，不要求三个 Composable 永远同时渲染。
- 搜索、歌单、专辑、歌手、本地音乐、云盘、设置、MV、Full Player 等二级页面统一压入 Tabs Shell 之上的全局页面栈。进入二级页面后隐藏主 Navigation Bar/Rail；返回时回到进入前选中的 Tab 及其原状态。
- 从发现或我的根页面执行系统 Back 时切换到已保存状态的首页；从首页根页面执行 Back 时退出 App 或返回系统上一任务，不在历史 Tab 之间循环。
- 点击任一 Tab 只切换选中根页面，不重新加载、不清空或滚到顶部；重复点击当前 Tab 默认无操作，刷新由页面显式操作触发。
- Full Player、MV 和登录也是全局页面；它们的特殊展示和续接行为不改变页面栈模型。Mini Player 的可见性遵循 7.9，Full Player 与 MV 不显示 Navigation Suite 或 Mini Player。
- 窗口变化保留全局当前页面、选中 Tab 和三个根页面状态。进程回收后恢复当前目的地及必要的查询、分类和筛选参数；可重新请求网络列表，不要求持久保存整份响应。
- App 已在前台时收到文件“打开方式”或“分享”Intent，导入流程压入当前全局页面栈；完成后显示“我的 → 本地音乐”，Back 恢复触发 Intent 前的 App 页面及状态。冷启动由文件管理器进入时，完成后同样显示本地音乐，但 Back 结束本次 Resonote 任务并返回文件管理器。
- Deep Link 或系统媒体入口进入详情时，先选择该内容归属的顶层 Tab，再把类型安全详情页压入全局页面栈；Back 返回该 Tab 的根页面。无法建立有效目标参数时遵循 7.17 的两层错误防御，不创建已知死路。

### 7.1 按需登录与操作续接

- App 启动后以匿名状态直接进入首页，不把登录作为启动门槛。
- 首页、发现和我的可以展示无需账号的内容；具体 API 返回或用户操作需要认证时，动态进入登录流程。
- 登录续接分为导航意图和原子操作：导航意图可以保存目标 Destination 与必要参数；原子操作不保存可执行命令、不可重放的 UI 对象或原始密码。
- 用户因进入云盘、账号资料等受限页面而登录时，成功后继续进入原目标页面，并由该页面正常加载内容。
- 用户因喜欢、收藏到歌单、确实要求账号授权的播放操作、切换受限音质、签到、上传、删除等原子按钮操作而登录时，成功后只返回并恢复原页面上下文，不自动执行或重试该操作；用户必须再次点击。匿名 VIP 歌曲的一分钟试听不要求账号授权，不得进入登录流程。
- 用户取消登录时返回原上下文，不执行受限操作，也不丢失当前页面的滚动、查询和筛选状态。
- Session 失效与首次按需登录使用相同入口；清理失效凭据后，导航意图可以恢复，原子操作仍需用户再次触发。这样可以避免重复写入、意外播放和登录后突发操作。
- 可见页面请求收到上游明确的 Session 失效、未登录或凭据过期状态码时，统一进入登录门禁，不由每个页面自行猜测或只展示普通网络错误。页面级加载登录成功后重新进入目标并重新请求；原子操作登录成功后只恢复上下文，仍需用户再次触发。
- 真正没有可见页面的后台请求不能直接拉起登录 UI；它只使当前 Session 失效并清除账号可见状态，App 回到前台或用户进入受限能力时再显示登录门禁。
- 验证码登录与密码登录共享登录完成合同；多账号选择、风控验证和错误恢复是登录流程内部状态。
- 验证码登录是默认方式；密码登录作为可切换方式，使用账号/邮箱字段和密码字段。
- 二维码登录只有在产品合同明确纳入时才提供，不因上游存在接口而默认展示。

### 7.2 本地文件导入

- App 内系统文件选择器的单选、多选、目录选择，以及 Android 文件管理器通过“打开方式”或“分享”交给 Resonote 的文件，全部复用同一导入管线。目录选择使用 Android 系统目录授权，不申请无边界的全盘文件权限。
- 导入前读取真实媒体信息并尝试使用 Media3/系统解码能力验证；文件扩展名和 MIME 只作线索，不作为唯一依据。无法识别、无法读取或设备不能解码的文件不导入，并报告具体原因。
- 导入时将源音乐文件持久复制到 App 管理目录，并解析可用的标题、艺人、专辑、时长、封面、格式、采样率、位深和码率信息。
- 复制及索引成功后写入本地音乐列表；后续播放不依赖源文件 URI 或源文件继续存在。
- 本地导入不要求登录；导入记录属于设备本地数据。
- 重复识别先用文件大小快速筛选候选，再以完整内容的 SHA-256 Hash 最终确认；文件名不同但内容完全相同仍视为重复，文件名相同但内容不同不视为重复。
- 检测到完全重复时不得静默处理。冲突弹窗展示已存在歌曲与来源，提供“取消”和“仍然导入”；用户确认“仍然导入”后进入副本模式，为新文件建立独立本地媒体身份，允许列表中同时存在两份副本。
- 同名但内容不同的文件正常导入，在 App 私有目录生成不冲突的物理文件名；歌曲展示名继续来自真实 metadata，不因存储重命名而改变。
- 多文件或目录导入展示总进度以及成功、跳过和失败数量，并允许取消尚未处理的任务。取消前已经成功复制并完成索引的文件保留；正在复制的临时文件回滚，复制失败或索引失败不得留下可播放的半成品记录。
- 空间不足、来源权限失效、读取中断、Hash 失败、媒体解析失败和格式不支持分别报告；批量任务允许部分成功，不把一项失败扩散为整批回滚。

### 7.3 首页

首页使用 Resonote 的 Android 信息架构和视觉系统，功能范围如下：

- 推荐电台，并支持切换当前 API 与产品合同已确认的推荐模式后直接开始播放。
- 排行榜快捷入口；进入发现的榜单子页面，不在首页刷新时预取榜单数据。
- 精选歌单快捷入口；进入发现的推荐歌单分类，复用推荐歌单数据能力，不硬编码个人歌单 ID。
- 每日推荐歌曲，支持播放单曲、播放全部和通用歌曲操作。
- 推荐歌单，并进入歌单详情。
- 新歌速递：首页展示 6 首歌曲的无分类预览，支持播放单曲、播放全部和通用歌曲操作；完整分页浏览仍属于发现页职责。
- 页面只在首页提供搜索入口；点击进入独立搜索页，入口右侧话筒进入独立听歌识曲页。
- 每个区块分别处理 Loading、Empty、Error、需要登录和部分数据可用状态；单一区块失败不应阻断整个首页。
- 首次加载与下拉刷新并发更新每日推荐、推荐歌单和新歌速递；单区成功只替换该区，单区失败保留旧内容，首次全部失败保持空状态。
- 每日推荐每次成功请求后从完整候选池重新洗牌并选取 6 首；不要求连续两次结果必然不同。
- 推荐电台按用户操作调用 `top_card`，默认私人好歌 `card_id=1`，同时支持 `2/3/4/6`；不纳入整页刷新请求。
- 排行榜入口的目标页使用榜单列表与榜单歌曲接口；推荐歌单卡片进入统一歌单详情并分页加载歌曲。这些按需请求属于首页可达闭环，不加入首页三个区块的并发刷新。
- 首页刷新采用请求代际约束，旧请求不得覆盖后发刷新已经提交的新内容或发布过期问题；旧代际返回明确的 `Superseded` 结果。本批仅保留进程内快照。

Compact 首页实现基准已冻结：

- 内容顺序为推荐区域 → 每日推荐 → 推荐歌单 → 新歌速递。
- 推荐区域固定为三张同宽、同高、同层级的 `1:1` 彩色入口卡，顺序为推荐电台、排行榜、精选歌单；卡间距为 `8dp`，标题使用加粗 `titleSmall`，辅助文案使用常规字重 `labelSmall`，卡色使用从主题语义色派生的轻微渐变。卡内使用设计稿原始线性图形资产，并保持波形、五柱榜单与同心唱片各自的视觉占比。电台卡只显示固定功能文案，不展示歌曲、歌手或封面等动态媒体信息；电台只通过 Compact Overlay Filled Icon Button 触发按需加载，保留 `48dp` 触控区，同时使用 `28dp` 可见容器和 `16dp` Glyph，可见容器与卡片右、下边缘各保留 `8dp`。另外两张卡整卡导航。
- 每日推荐固定 6 个 Music Item，并共用一个外层卡片容器；Section Action 为“播放全部”。
- 推荐歌单固定 6 个 Playlist Item，Compact 固定两列；标题右侧无 Action。
- 新歌速递固定 6 个 Music Item，并共用一个外层卡片容器；不显示分类筛选，Section Action 为“播放全部”。
- Top App Bar 与 Bottom Navigation 固定；Mini Player 是高于滚动内容的悬浮 Overlay。Item 可以在滚动过程中从其后方经过，但列表末尾必须有足够 Content Padding，保证最后一个 Item 可完整滚动到悬浮层上方。
- 页面结构、滚动层级和信息密度以当前 Compose 实现与 Roborazzi 基线为准；组件细节仍以 08/09 合同为准。

卡片样式切换、装饰图片、彩蛋、桌面 Hover 和具体栅格不属于首页功能合同。

### 7.4 发现

发现使用独立的 Android 页面结构，功能范围如下：

- 分类歌单：加载分类标签、切换分类、浏览歌单并进入详情。
- 音乐榜单：浏览榜单及歌曲、分页加载、播放单曲和播放当前榜单。
- 新碟上架：按上游支持的类型筛选、浏览专辑并进入详情。
- 新歌速递：分页浏览、播放歌曲并使用通用歌曲操作。
- 子功能切换、筛选和分页状态在切换顶层 Tab、窗口变化及进入详情返回后保持。

分类切换器、卡片布局和滚动表现以 Resonote 当前 Android 页面合同为准。

### 7.5 我的 / 音乐库

“我的”按 Resonote 的产品结构承载以下已确认能力：

- 个人资料与 VIP 状态。
- 最近播放包含账号在线历史与设备本机历史两个分类，并支持从当前分类播放单曲或播放全部。
- 我喜欢、创建的歌单、收藏的歌单和收藏的专辑。
- 关注的歌手。
- 好友资料只读展示；不可点击进入详情，不提供关注、聊天、动态或其他社交操作。
- 创建歌单。
- 本地音乐入口及已导入音乐列表。
- 云盘入口及账号云盘音乐。
- 每日签到领取 VIP，并在允许时选择是否升级概念版 VIP。

上述用户能力、业务规则与状态覆盖均由 Resonote 当前合同定义，不从其他产品继承分类、布局、文案或交互。

### 7.6 每日 VIP

- 每日 VIP 是“我的”中的重要账号功能，要求登录；匿名用户触发时进入按需登录流程。
- 登录成功后返回“我的”并保持每日 VIP 入口可见，但不自动签到；用户需要再次点击确认本次原子操作。
- 用户发起签到后调用每日领取能力；成功时明确展示获得 1 天畅听 VIP，并刷新个人 VIP 状态。
- `131001` 或等价“今日已签到”是中性完成状态，不显示为失败。
- 签到成功或今日已签且服务允许升级时，询问是否继续升级概念版 VIP；用户可以明确选择暂不升级。
- 升级成功后刷新 VIP 状态；一天仅一次或已完成时展示中性结果，不重复提交。
- `20028` 或等价风控状态不提供升级入口，提示用户需要前往官方客户端处理。
- 网络、协议及其他服务错误保持可重试，不伪造签到成功，也不在后台自动签到。
- 每日 VIP 的状态语义以当前 Network 分类、Repository 映射和页面测试为准。

### 7.7 云盘

- 云盘页面要求登录；从入口登录成功后继续进入云盘页面。由播放、上传或删除等原子操作触发登录时，只恢复云盘上下文，不自动继续该操作。
- 展示歌曲总数、总容量、已用容量和可用容量，并支持分页加载。
- 支持按名称/艺人搜索、按可用字段排序，以及列表/网格两种查看方式。
- 支持播放单曲、播放当前结果、追加整个结果或选中歌曲到统一 Queue，并定位当前播放歌曲。
- 支持选择多个本地音频上传，展示总进度与逐文件结果；文件格式、单文件大小和剩余容量按上游能力校验。
- 支持批量选择和删除；部分文件无法删除时保留其记录并清楚报告部分成功，不进行乐观假删除。
- Android 原生协议层实现云盘列表、上传、删除和播放地址解析，不运行本地转发服务；生产 Endpoint、字段和错误语义由当前 Network 测试与纵向切片验证。
- 云盘播放地址只用于在线播放，首版不提供云盘下载；若上游合同变化，必须重新完成产品确认，不能根据 URL 自动推导下载能力。

### 7.8 本地音乐列表模型

- 本地音乐是一个由系统维护的特殊音乐列表，而不是独立的播放体系。
- 它复用普通歌单的歌曲列表、单曲播放、播放全部、加入播放队列、当前播放标识、搜索、排序、空状态和错误状态。
- 在线歌曲、本地歌曲和云盘歌曲进入同一个当前播放队列；播放来源差异由 Track Source 表达，不建立第二套 Queue。
- 本地音乐列表的成员由导入和删除本地副本维护，不向远端同步，也不伪装成服务端歌单 ID。
- 本地歌曲不加入在线歌单或在线“我喜欢”，也不上传为账号播放历史。
- 本地播放进度、最近播放等设备内状态可独立保存，但不得伪装成服务端同步结果。
- 删除本地歌曲必须二次确认；确认后同时删除 App 私有媒体副本并从本地列表移除。若该歌曲在 Queue 中或正在播放，按 7.13 已确认的当前项移除规则更新播放状态，不保留指向已删除文件的 Queue 项。
- 首版元数据只读：显示解析到的歌曲名、艺人、专辑、封面、时长和真实音频信息，但不提供修改标签、替换封面或写回文件的能力。

### 7.9 Mini Player 与 Full Player 入口

- Mini Player 是 App Scaffold 的常驻产品区域，在首页、发现、我的及其子页面间保持同一播放状态。
- 尚无当前媒体时不展示空白 Mini Player；首次形成 Queue 后出现，并在切换 Tab、进入详情和返回时持续存在。
- Compact 布局中 Mini Player 位于页面内容与 Navigation Bar 之间；Rail 布局中与内容区组合，不遮挡系统 Insets、导航或页面操作。
- Compact Mini Player 使用已冻结的独立悬浮卡片：Start、End 以及与 Navigation Bar 顶部的间距均为 16dp；卡片与 Navigation Bar 使用相同 Container Semantic Color，但不得贴合、共边、融合或重叠。
- Mini Player 的歌曲信息复用 Music Item 层级：Title、Quality Badge 与 VIP Badge 位于同一首行，Title 空间不足时优先省略；Artist 位于第二行。播放控制与 Queue 入口保持独立 Touch Target。
- 点击 Mini Player 的歌曲主体区域直接展开 Full Player，不经过 Modal Bottom Sheet 或中间预览层。
- Mini Player 同时提供当前播放列表/Queue 入口；用户可以不进入 Full Player 就直接查看和管理同一 Queue。Queue 最终使用 Sheet、Pane 还是独立页面在 Player 页面设计阶段决定，不改变入口能力。
- Full Player 与 Mini Player 观察同一个 Playback Controller、当前歌曲、进度和 Queue，不复制播放状态。
- Full Player 左上角继续使用当前向下箭头，语义为“收起播放器”；不采用历史设计图的左向返回箭头。点击该操作、Android 系统 Back 与预测返回使用同一退出路径。
- Mini Player 展开为 Full Player、Full Player 收回 Mini Player 时使用双向 Hero 过渡。主共享边界连接同一媒体 ID 的 Mini Player 外层容器与 Full Player 根容器，因此封面页和歌词页都能连续展开/收起；进入封面页时，真实封面再作为第二共享元素从 Mini Player 的 `56dp` 封面位扩展到 Full Player 封面位。
- 双向 Hero 使用可感知为容器展开/收拢的慢速空间动效；Mini Player 端点同步渐隐/渐显，不能以快速页面淡入淡出取代空间语义。系统启用减少动态效果时使用瞬时安全降级。
- Full Player 的歌曲信息、Pager 指示、进度、播放控制、工具和歌词不是独立 Hero 元素，按 Resonote Motion 淡入/淡出。用户在歌词页收起时不得先切回封面页，也不得为动画制造隐藏假封面；此时由始终存在的根容器完成反向 Hero。
- 从 Full Player 返回时恢复之前的页面、滚动和筛选状态，播放不中断。动画不得改变 Queue、播放位置、播放/暂停状态、歌词状态或 Pager 选择，也不得触发重复导航。
- 没有可匹配 Mini Player、媒体 ID 在过渡期间改变、共享元素端点不可用或系统要求减少动态效果时，安全降级为标准页面过渡，不阻断进入或返回。Hero key 必须包含稳定媒体身份，禁止旧歌曲端点过渡到新歌曲。
- Full Player 的封面页与歌词页确定使用横向 Pager 切换；这是已冻结的交互结构。默认首屏、两页内部信息层级、操作布局、Queue 容器和自适应细节仍在 Player 产品设计阶段讨论。
- Full Player 只有中间内容区是 Pager：第一页显示封面，第二页显示歌词。顶部栏及 Pager 下方的页码指示、歌曲信息、播放进度、完整主播放控制和已确认的播放工具属于共享页面骨架；切到歌词页后仍保持完整显示、位置一致且全部可操作，不折叠或替换成简化控制。
- Full Player 使用当前歌曲封面派生的统一语义色板；封面页、歌词页与共享控制不得分别取色。色板必须在 Full Player 首帧显示前准备完成，进入页面后不得先显示默认色再整体跳变为封面色。
- 歌曲信息使用轻量 Bottom Sheet，不显示独立页面 Header。封面、歌曲名和艺人构成紧凑头部；专辑、时长与音质收纳到独立圆角信息容器。歌曲名、艺人和专辑保留轻量点击反馈，点击后分别以对应文本进入全局搜索的单曲、歌手和专辑分类；不使用网页式蓝色下划线。

### 7.10 搜索

- 搜索入口只位于首页；点击后进入独立搜索页面。发现、我的及其二级页面不重复提供全局搜索入口。
- 全局搜索只查询在线内容。本地音乐和云盘文件继续使用各自页面内的搜索，不混入全局结果，也不把本地查询发送到在线接口。
- 搜索历史保存在本机，按最近使用排序并去重，最多保留 20 条；支持删除单条和清空全部，不依赖登录，也不跨账号或设备同步。
- 热门搜索和输入建议只有在 Android API 纵向切片验证可用后才显示；接口不可用或失败时隐藏对应内容，不阻断手动提交搜索。
- 结果支持综合、单曲、歌单、专辑、MV 和歌手六类。综合页聚合各类摘要，各独立分类分页加载；切换分类和返回页面时保留查询、分类、已加载结果与滚动位置。
- 点击单曲采用 7.13 已确认的插播逻辑；歌单、专辑和歌手进入各自独立详情页；MV 进入独立视频播放页。
- 各分类独立处理 Loading、Empty、Error、分页、登录要求和不可播放状态。登录成功后恢复原查询、分类和滚动位置；被登录打断的播放、收藏等原子操作仍需再次点击。
- 搜索框右侧话筒是听歌识曲入口，不在搜索页内直接开始录音。

### 7.11 听歌识曲

- 听歌识曲是独立页面，其能力、失败状态和恢复路径由 Resonote 当前合同定义。
- 页面至少覆盖待开始、请求麦克风权限、录音中、识别中、成功、无匹配、录音过短、网络失败和可重试错误。
- 用户明确开始后才采集麦克风；录音最长 10 秒，可提前停止，少于 1 秒不提交识别。时长是当前产品合同，API 约束变化后可修订。
- 开始采集前暂停 Resonote 自身播放，避免识别到当前正在播放的歌曲；识别完成后不自动恢复，是否继续播放由用户明确操作决定。
- 成功结果按匹配度展示候选歌曲，可直接播放，也可携带歌曲名与艺人进入搜索页继续查找。
- 原始录音与中间 PCM 只用于本次识别，任务完成、取消或失败后立即删除，不进入媒体库、云端历史或分析埋点。
- 麦克风被拒绝时解释用途并允许重试；永久拒绝时提供进入系统设置的明确操作，不阻断普通搜索和播放。

### 7.12 音频焦点与系统媒体通知

- 设置提供三档并行播放意图：`所有场景`、`部分场景`、`不允许`。选择立即应用于后续播放，并持久保存在设备设置中；默认使用 `不允许`。
- 三档决定的是长期或互斥音频出现时是否继续播放，不取代 Android 的临时 Ducking 语义。导航播报等请求 `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` 的场景中，Resonote 应保持播放、暂时降低音量，并在临时请求结束后自动恢复。
- Ducking 是运行时瞬时状态，不写入音频焦点设置或用户音量。只恢复由本次 Ducking 降低的音量；如果用户在期间主动调音量、暂停或停止播放，不得用自动恢复覆盖用户操作。
- `所有场景` 表示尽可能与游戏、影音、直播、短视频及录制等非通话音频并行，但它是 best-effort 用户意图；电话、系统隐私策略及 Android 12+ 强制淡出/静音仍可覆盖该选择。
- `部分场景` 表示与系统声明为媒体/游戏用途的影音、游戏、直播及部分短视频并行，而在录音、语音/视频通话等通信场景让出播放。实现可以组合活动播放的 `AudioAttributes.usage`、Audio Mode 和活动录音状态，不依赖竞争 App 的包名或身份。
- 系统 usage 由其他 App 自行声明，音乐、视频、直播和短视频也常共用 `USAGE_MEDIA`，因此该档承诺的是“按公开系统音频类别尽力适配”，不是精确识别具体 App 或内容类型。
- 持久化的用户选择与当前设备实际执行的策略分离。API 版本过低、所需信号缺失或信号矛盾时，本次运行的有效策略降级为 `不允许`，但不得改写用户保存的 `部分场景`；设置页保留原选择并展示兼容说明，条件恢复后自动重新尝试部分场景策略。
- `不允许` 完整遵循 Android 标准媒体音频焦点：可 Duck 的临时竞争降低并恢复音量，临时独占或长期丢失则暂停；焦点重新获得后的自动恢复条件由本合同、当前播放实现与对应测试共同约束。
- `部分场景` 或 `所有场景` 若因并行播放策略未使用平台自动 Ducking，Playback service 必须依据焦点事件或公开的导航音频 usage 实现等价的临时压低与恢复；同一事件只能由系统或 Resonote 一方处理，禁止重复 Ducking。
- 无论选择哪一档，普通电话、规范使用系统通信 Audio Mode 的语音/视频通话、系统强制策略与用户主动暂停始终优先。通话开始后暂停且结束后不自动恢复；设置页应使用结果导向说明，不宣称绕过 Android 或其他 App。
- 播放期间提供由 MediaSession 状态和 metadata 生成的标准媒体通知，至少显示歌曲、艺人、封面、播放/暂停和切歌，并承接锁屏、耳机及系统媒体控制。
- Resonote 对“上岛”的实现合同止于提供状态正确的 MediaSession、MediaStyle 媒体通知与系统所需 metadata/actions；Android System UI 可自动把它呈现为岛形、状态栏 chip、锁屏卡片或其他媒体表面。
- 不主动申请 Live Updates，不为“上岛”额外发布重复通知，也不适配某个 OEM 的私有岛形组件。系统不展示岛形入口时，标准媒体通知仍完整可用。

### 7.13 播放与队列

- 在线、本地和云盘歌曲共享同一个当前 Queue；来源只影响地址解析、可用操作和错误恢复，不建立独立播放器。
- 用户从任意歌曲列表点击单曲时立即播放该曲；若不在 Queue 中则插入当前歌曲之后，不用来源列表替换整个 Queue；若已存在则跳转到原队列位置，不创建重复项。
- 单曲点击必须先完成播放地址解析，再提交 Queue 与播放器切换。解析失败时不插入/选中失败歌曲，不停止、清空或重置当前播放，只显示失败提示；没有当前播放时保持空闲状态。
- “下一首播放”插入当前歌曲之后但不中断当前播放；连续添加多首时保持用户添加顺序。“加入队列”追加到队尾并按稳定媒体身份去重。
- 明确点击“播放全部”才使用当前列表替换 Queue，并从列表第一首开始；分页尚未加载完成时，后续数据只在 Queue generation 未变化时继续追加并去重。
- Queue 支持跳转、移除、清空和拖拽重排。移除当前歌曲时继续播放其后第一首；已经是末项时播放新的末项；移除最后一项等同清空并停止播放。
- Queue、当前歌曲、当前进度和播放模式持久化。进程回收、App 冷启动或设备重启后恢复这些状态，但默认保持暂停，必须由用户、系统媒体恢复入口或明确自动播放场景继续。
- 播放模式完整保留四种：列表循环、随机播放、单曲循环和顺序播放。列表循环在队尾返回队首；顺序播放到队尾后停止，二者必须使用清晰名称与状态语义区分。

播放失败遵循以下分层恢复合同：

- 在线歌曲先按用户目标音质逐级回退到可用音质；只有全部候选都失败后才判定该曲不可播放。
- 匿名用户点击支持试听的 VIP 歌曲时，直接请求并播放一分钟试听源；进入试听、显示 VIP 提示和到达试听边界均不得发布认证门禁或跳转登录。试听结束后按试听边界策略暂停或继续 Queue，不自动重试完整歌曲。
- 无版权、普通歌曲 URL 失败、云盘 URL 失败或本地副本读取失败时，保留失败项和原因，显示 3 秒自动切换提示，然后尝试下一首。
- 初始歌曲失败后最多执行 5 次自动切换，即最多再尝试后续 5 首；第 5 次切换后的目标仍无法播放时停止，保持 Queue，并要求用户手动选择或重试。
- 任一歌曲成功开始播放，或用户主动选择歌曲、清空/替换 Queue 后，连续失败计数清零。
- 登录失效、账号风控、需要登录或必须由用户处理的授权错误不自动跳过；进入对应恢复流程后返回原上下文，但不自动重试原歌曲，用户需要再次点击播放。
- 单曲循环下若当前歌曲不可播放，不对同一失败项无限重试；仍按上述失败规则进入下一可处理动作。

### 7.14 Player 操作、歌词、音质与播放工具

Player 的功能合同与具体布局分开冻结：

- 播放/暂停、上一首、下一首、进度、播放模式和 Queue 是核心播放操作。
- Full Player 的进度条参考现行 MV `VideoSeekBar`：可见轨道为 `3dp` 圆头细线，区分已播放、已缓冲和剩余三层；静止 Thumb 为 `8dp`，拖动时过渡到 `14dp`。视觉保持细长，但完整交互高度为 `48dp`，支持点击定位、水平拖动和无障碍 `setProgress`。
- Full Player 复用 MV 的进度层级、尺寸和交互语义，不复用视频黑色 Overlay 的固定颜色。已播放轨道与 Thumb 使用当前 `PlayerPalette` 强调色，缓冲与剩余轨道使用同一色板中通过对比校正的较低强调内容色；封面页与歌词页显示完全相同的进度条。
- 轨道下方左侧显示当前时间、右侧显示总时长。拖动时 Thumb 与左侧时间即时预览目标位置，松手后再提交 Seek；播放器晚到的进度更新不得在拖动期间拉回 Thumb。位置、缓冲和总时长均需裁切到有效范围，缓冲层不得落后于已播放层或超过总时长。
- Full Player 右上角 Overflow 使用底部弹窗，直接提供“下一首播放”“加入队尾”“添加到歌单”“歌曲信息”和“歌词设置”，不再通过二级“歌曲操作”入口跳转。
- 所有歌曲上下文提供“立即播放”“下一首播放”和“加入队列”。“加入队列”追加队尾；歌曲已在 Queue 时按稳定媒体身份去重，不制造副本。Full Player 当前歌曲已存在于 Queue 时可以隐藏或禁用无效果的追加操作。
- 喜欢和收藏到歌单要求登录。任何由原子操作触发的登录都不在成功后自动执行，用户需要再次点击。
- 当前版本不提供歌曲、MV、歌单或其他内容的对外分享入口，也不生成分享链接、不调用系统分享面板或执行分享网络请求。Android 文件管理器将音频分享给 Resonote 仍属于本地导入入口。

Player 封面取色与回退：

- 当前播放项存在可解码封面时，以原始封面位图作为取色输入，在进入 Full Player 之前生成一次 `PlayerPalette`。模糊背景、遮罩、缩放或其他展示处理后的图像不得反向作为取色输入。
- `PlayerPalette` 是当前媒体项的单一视觉事实，至少提供背景、背景层级、强调色、主要文字/图标、次要文字/图标以及强调色上内容等语义角色。封面页、歌词页、进度、播放按钮、Pager 指示、Overlay 与系统栏外观消费同一份色板。
- 播放组件必须具备来自 Resonote 当前主题的默认语义色板。没有封面、封面加载或解码失败、采样结果不可用、取色取消，或者进入页面前未能得到有效色板时，直接使用默认色板；不阻断播放、不延迟导航、不显示取色错误，也不在页面打开后用迟到结果突然换色。
- 取到的原始颜色必须经过明度、色度与前景对比校正，保持封面色彩倾向的同时满足文字、图标、进度、状态层和系统栏可读性；不得把单个主色未经校正地用于所有组件。
- 同一媒体项的色板在该次可见生命周期内保持稳定。页面重组、封面页/歌词页切换、歌词加载与滚动不得重复取色。切歌时新色板与新歌曲资料原子切换，旧歌曲晚到的取色结果不得覆盖当前歌曲。
- 取色只处理本机已取得的封面资源并允许按媒体与封面缓存标识复用，不新增网络请求、埋点、遥测或账号画像数据。

歌词能力：

- 支持时间轴同步、自动滚动和点击某行跳转；用户手动滚动时暂时停止跟随，约 3.5 秒无继续操作后恢复。
- KRC 或等价数据包含字符时间轴时逐字高亮；只有行时间轴时降级为逐行高亮。
- 原文始终是歌词的主要信息层。当前行使用更大的字号、更强的字重和最高的色彩强调；相邻非当前行使用较小字号和较低对比度。层级主要通过文字颜色、大小与字重表达，不要求为当前行增加独立卡片或填充背景。
- 逐字时间轴只强化主要歌词：已经播放、当前和未播放的字或音节使用 `PlayerPalette` 中不同强度的内容/强调色表达进度。翻译与音译维持行级辅助样式，不与原文争夺逐字高亮焦点。
- 翻译与音译是两个独立持久化开关，默认都开启；两者同时存在时按“原文、翻译、音译”顺序显示，用户可分别关闭任意一项。某项缺失或关闭时直接省略，不为其保留空白占位。
- 翻译或音译只在存在真实非空数据时显示，统一使用小于原文的字号、较弱字重和较低对比度；即使当前行处于高亮状态，辅助文本也不得超过原文的视觉优先级。没有辅助数据时不保留空白占位，也不显示无内容选项。
- 保留滚动/单行、逐字/逐行、左对齐/居中、小/中/大字体，以及默认背景/封面背景/关闭背景设置。视觉样式以后按 Resonote 独立设计。
- 覆盖 Loading、无歌词、纯音乐、解析失败、网络失败和重试；这些状态只替换 Pager 内的歌词内容，不改变外部共享播放控制，歌词失败也不影响歌曲继续播放。

音质与声音能力：

- 在线音质完整支持 128K 标准、320K 高品、FLAC 无损、Hi-Res、蝰蛇全景、蝰蛇超清和蝰蛇母带；选择时由上游按当前歌曲、账号与版权资格解析，失败必须保留原播放并给出明确原因。
- Full Player 的音质入口使用底部单选弹窗；选择结果只覆盖当前 Queue 中该歌曲的本次播放，不写入全局默认音质。未覆盖歌曲仍读取播放设置中的全局默认值。
- 单曲音质切换保留当前进度和播放/暂停意图，只有新地址解析成功后才替换队列项；失败继续使用原地址和原选择，不把半完成状态写入当前歌曲。
- 登录、VIP、版权或上游限制必须显示明确原因。切换音质保持当前进度及播放/暂停状态；目标音质失败时按既定音质链逐级降档。
- 本地音乐展示文件真实格式、采样率、位深和码率，不伪造在线音质档位。云盘展示服务端实际返回的播放版本。
- 支持 `0.5×`、`0.75×`、`1×`、`1.25×`、`1.5×`、`2×` 倍速，默认 `1×` 并持久保存用户选择。
- 支持响度均衡，默认关闭；优先使用上游提供的响度、建议增益和峰值数据，限制增益以避免削波。缺少可靠数据时保持原始响度，不伪造归一化结果。
- 睡眠定时支持 10、20、30、60 分钟以及当前歌曲结束后停止；展示剩余时间并允许取消。倒计时结束时短暂淡出后暂停，不清空 Queue。
- 用户可调音量只使用 Android 系统媒体音量，不建立 Resonote 独立音量值或滑杆；硬件键、蓝牙绝对音量和系统媒体面板共同控制该音量。Ducking 只施加临时播放器增益，结束后恢复，不改写系统音量。

### 7.15 高级播放与音频设备

- 支持无缝播放。相邻曲目、解码器和来源允许时提前准备下一首，曲目边界不插入人为静音；设备或格式不支持时正常切换，不伪装为无缝成功。
- 支持交叉淡化关闭、3 秒、5 秒、8 秒四档，默认关闭并持久保存。开启后在自然换曲时让前一首淡出、后一首淡入；它与无缝衔接互斥，交叉淡化优先。单曲循环、手动 Seek、错误跳过和睡眠定时不强制制造完整交叉淡化。
- 不提供 Resonote 自建均衡器、低音增强或虚拟环绕。蝰蛇全景/超清/母带是上游音质版本，不等同本地音效处理。
- 音频输出设备交由 Android 系统 Output Switcher / MediaRouter 管理；Resonote 不维护第二套蓝牙、扬声器或耳机设备列表，也不自行持久化路由选择。
- 蓝牙、耳机和系统媒体控制支持播放/暂停、上一首、下一首、进度、当前歌曲 metadata 与可用命令；实际按钮数量由设备能力决定。
- 拔出有线耳机或断开当前蓝牙输出时立即暂停并保留位置。重新连接后不自动恢复，必须由用户明确播放；主动从系统 Output Switcher 切换到另一个有效输出不视为意外断开。
- Android Auto 与 Google Cast 明确排除；系统 Output Switcher 和普通蓝牙播放不代表支持车载媒体浏览或 Cast 远端播放。

### 7.16 MV / 视频播放

- MV 是已确认的产品能力，不再只是搜索结果占位。V1 从搜索 MV 分类进入独立视频播放页；API 验证支持时，歌曲详情提供“相关 MV”，艺人详情提供“视频 / MV”分类。页面和交互按 Resonote Design System 与 MD3 Adaptive 独立设计。
- 搜索结果至少展示封面、MV 名称、歌手、时长和真实可用的发布日期；字段缺失时降级展示，不伪造内容。
- MV 点击属于原子播放操作。若进入前已能根据 Session 或 MV privilege 明确判断为未登录、Session 失效或凭据无效，则先进入登录门禁，不创建视频播放页、不暂停当前音乐，也不解析或播放视频；登录成功后返回来源上下文，用户必须再次点击。VIP 不足、版权/地区限制、内容下架或没有可用版本不属于认证失败，应显示对应不可播放原因，不进入登录门禁。
- 已具备播放条件时，用户点击 MV 后先暂停当前音乐，保留原 Queue、歌曲与进度，再进入视频页、解析地址并自动播放 MV。视频播放不替换音乐 Queue，也不把 MV 写成音频歌曲；退出 MV 后原音乐保持暂停，不自动恢复。
- 若进入视频页后，详情或地址请求才返回 Session 失效、未登录或凭据无效，则停止解析与播放并进入登录门禁；登录成功后只恢复视频页的待播放/错误上下文，不自动重试或突发播放。晚到的 VIP、版权、地区或版本限制留在视频页显示明确错误，不拉起登录。
- 播放控制支持播放/暂停、进度拖动、系统音量和明确的全屏操作。MV 页面默认竖屏；用户点击 Video Player 的全屏操作后，由视频播放功能请求 App 的统一方向协调能力切换为横屏沉浸式全屏，退出全屏或离开 MV 时恢复竖屏。全程不响应传感器自动旋转，也不因设备转动自行进入或退出横屏。只有 API 返回多个真实可用版本时才显示清晰度切换。
- 横屏是同一个 Video Player 的全屏状态，不是新的页面或独立信息架构。V1 不单独制作横屏 MV 页面设计稿；横屏直接复用播放器画面、控制层和 Material/Media3 可用行为，只验证全屏进入/退出、系统 Back、控制可达性、Insets、生命周期与方向恢复。
- 播放页覆盖加载、参数缺失、认证要求、VIP/版权/地区/下架/无版本等播放资格限制、地址不可用、网络失败、格式不支持、播放错误和重试；退出或销毁页面时停止视频并释放其媒体资源。
- V1 不提供后台视频或画中画；离开 MV 页面即停止视频。MV 点赞、收藏、下载和对外分享不进入 V1。
- 艺人视频、歌曲关联 MV 和视频详情必须经过 Android API 验证后才显示入口或字段；接口存在不等于当前可用，失败时不得展示无效入口。

### 7.17 内容详情与收藏组织

- 歌单、专辑和歌手详情都是 V1 Must，可从首页、发现、搜索、我的及其他内容入口进入。三者使用独立目的地、参数和状态模型；歌曲列表、播放操作和通用状态可以复用。
- 歌单分为用户自己创建的歌单与其他人的歌单。只有自建歌单有权修改名称、简介、封面和歌曲内容，也可以删除歌单；其他人的歌单只允许收藏/取消收藏，不提供伪装可用的编辑入口。
- 歌单详情展示封面、名称、创建者、简介、歌曲数、更新时间和歌曲列表，并提供播放全部、收藏/取消收藏及批量操作，不提供对外分享入口。
- 歌单支持批量选择歌曲并执行“下一首播放”“加入队尾”“添加到其他歌单”；只有自建歌单额外支持批量移除。所有写操作遵循 7.1 的原子登录规则，登录成功后不自动重放原操作。
- 专辑详情展示专辑资料、艺人、发布日期和歌曲列表，支持播放全部与收藏/取消收藏；专辑内容不可编辑。
- 歌手详情展示资料、关注/取消关注、热门歌曲、最新歌曲、专辑和 MV；各分类独立处理分页、Loading、Empty、Error，并在返回和窗口变化后恢复分类、已加载内容与滚动位置。
- 点击歌曲的有效艺人或专辑引用分别进入歌手或专辑详情。来源列表在导航前已经明确知道没有有效 ID 时，不进入已知无法加载的详情页；入口置为不可用，并就地提示“暂无可用详情”。无法预先判断、已经进入详情后才发现参数缺失、ID 失效、内容删除或接口无法解析时，显示完整错误页面并提供返回，可恢复错误才提供重试。
- “歌曲信息”使用 Material 3 底部 Sheet，而不是独立页面；以封面、歌曲和艺人建立紧凑信息头部，并在圆角信息容器内展示专辑、时长及真实可用的音质等字段，缺失字段直接省略。歌曲名、艺人和专辑分别是搜索入口，点击关闭 Sheet，并以对应文本自动提交到单曲、歌手或专辑分类；Back 恢复来源 Full Player 和原 Pager 状态。

### 7.18 播放缓存与离线下载

- 在线歌曲操作提供“下载”。任务由 Media3 下载管线持久管理，支持排队、暂停、继续、失败重试和删除；正在下载的任务使用前台服务承接，不依赖发起页面继续存在。
- 在线播放使用有容量上限、可自动淘汰的流式缓存，以减少重复流量和卡顿。缓存是性能优化，不保证无网络时仍能完整播放，也不在 UI 中标记为“已下载”。
- 设置页展示播放缓存占用并提供“清除缓存”。清除只删除可再生成的流式音频缓存；封面图片缓存不属于该操作范围，Queue、播放进度、收藏、历史、搜索历史、账号与云盘数据、本地音乐及其持久副本也不得受到影响。
- 文件导入后保存在 App 私有目录的持久副本属于本地音乐，不是缓存；任何“清除缓存”操作都不得删除、移动或取消其索引。
- 云盘歌曲继续通过上游播放地址在线播放，不因流式缓存命中而变成本地音乐，也不提供下载到本地。
- 下载文件保存在 App 私有目录，使用不受流式缓存 LRU 影响的独立持久缓存，不额外复制或导出。下载完成后自动作为成员聚合到“本地音乐”；它仍保留在线歌曲身份、歌词与队列语义，不伪装为手动导入文件。
- 下载管理是设置下的独立页面，展示全部任务及状态。本地音乐仅在存在进行中或失败任务时显示状态入口，点击进入下载管理。
- 从下载管理或本地音乐删除已下载歌曲前必须确认；删除同一份下载文件后，该歌曲同步从本地音乐消失。清除播放缓存、退出登录、Session 失效或切换账号不得删除下载。

### 7.19 设置

- 设置从“我的”进入独立页面，按外观、播放、歌词、缓存与存储、权限、通用操作和关于组织；具体分组层级与自适应布局在页面设计阶段确定。
- 外观提供“跟随系统”“浅色”“深色”“AMOLED”四种主题模式，并支持 Android 动态取色。动态取色只有平台和设备支持时可用；关闭或不支持时使用 Resonote 品牌色，不改变所选明暗/AMOLED 模式的语义。
- 首版用户界面只提供简体中文，不展示没有资源可切换的语言选择器。工程继续使用 Android 资源本地化、可扩展文案和 Locale-safe 格式，不把中文硬编码进业务逻辑，为后续多语言保留真实适配环境。
- 播放设置集中提供默认在线音质、播放模式、无缝播放、交叉淡化、倍速、响度均衡和三档音频焦点。选项必须观察同一 Repository/Playback state，不能与 Player 内的即时修改形成两份状态。
- 睡眠定时属于当前播放会话的临时操作，只从 Player 发起和查看，不作为全局持久设置出现在设置页。
- 歌词偏好全局持久化，可在 Full Player 快速修改；设置页也提供进入独立歌词设置页的入口，二者读写同一状态。歌词设置包括 7.14 已确认的显示模式、高亮、对齐、字号和背景选项。
- 设置提供独立下载管理入口；缓存设置仍只展示流式播放缓存占用并提供清除操作，不允许用户选择任意文件目录；清除范围遵循 7.18，不能影响下载、本地导入或其他持久媒体。
- 通知、麦克风等 Android 权限不使用与系统状态脱节的假开关。设置页展示当前权限状态和用途，需要修改时跳转对应 Android 系统设置；返回 App 后重新读取真实状态。
- “重置设置”操作前必须二次确认，只恢复主题、播放、歌词等用户偏好默认值；不退出账号，不删除本地音乐，不清除 Queue、播放历史、搜索历史、收藏或云盘数据。
- 不提供桌面平台启动页、系统字体选择、全局快捷键、代理/API 地址、自定义输出设备、后台节流和应用内自更新；桌面歌词仅按 Resonote 当前悬浮播放控制器合同实现。
- “关于”展示版本、开源许可、隐私政策和项目链接。应用更新由应用商店或安装渠道承接，Resonote 不内置安装包下载器或自更新流程。

### 7.20 账号退出、换号与 Session 失效

- 退出登录必须由用户在确认弹窗中批准；完成后关闭账号专属二级页面并返回“我的”匿名状态，不停留在云盘、资料或其他已失去访问权的内容中。
- 退出、换号或 Session 失效时立即清除本机凭据，以及当前账号的个人资料、VIP、喜欢、创建/收藏歌单、收藏专辑、关注歌手、账号播放历史、云盘列表和其他账号作用域 UI 数据。账号二级页面默认在重新进入时请求最新数据，不展示上一个账号的快照。
- 本地音乐、统一 Queue、当前进度、播放模式、主题、歌词偏好、音频焦点设置和本地搜索历史属于设备状态，不因退出、Session 失效或更换账号清除。
- 正在播放普通公开在线歌曲时退出账号允许继续播放；下一次解析地址、切换音质或重新播放时按匿名权限重新判断。
- 正在播放云盘、VIP 专属或其他账号授权内容时退出、换号或确认 Session 失效，立即暂停并提示需要登录。歌曲 metadata 可以留在 Queue，但标记为当前不可播放，不自动切到下一首或自动重试。
- 账号专属播放地址、云盘临时数据和受保护媒体缓存按账号隔离，并在退出或换号时失效/清除；公共流式缓存可以保留，禁止新账号读取旧账号授权内容。
- 新账号登录成功后，先切换账号作用域并清空旧账号可见状态，再请求新账号的资料、VIP、收藏、历史和云盘；旧请求晚到时不得覆盖新账号数据或重新显示旧账号内容。
- V1 只保留一个当前账号，不提供本机已保存账号列表或一键切换。更换账号通过退出后重新登录；登录接口返回的多账号选择只属于本次登录流程内部状态。
- Session 失效由上游明确的业务状态码/认证响应驱动统一登录门禁。前台页面级请求可以立即进入门禁并在成功后重新加载目标页面；前台原子操作可以进入门禁但不自动重试；后台无可见 UI 时只记录失效，等待前台恢复。

### 7.21 最近播放与历史

- “我的 → 最近播放”提供“在线”和“本机”两个分类。在线分类登录后通过当前 Android 纵向切片读取账号听歌历史。
- 匿名状态不展示退出前账号的在线历史。用户进入在线历史时触发页面级登录门禁；登录成功后继续进入历史页面并重新请求当前账号数据。
- 本机分类记录本地音乐和云盘歌曲的设备内最近播放，不把它们上传到普通在线账号历史。云盘记录保留云盘来源标识；账号失效后可以显示 metadata，但重新播放仍需通过登录门禁获取权限。
- 本机歌曲在真实开始播放并累计达到 10 秒后记入历史；总时长不足 10 秒但完整播放结束时也记录。Seek 跳过、预缓冲、加载失败和不足阈值的误触不记录。
- 同一稳定媒体身份重复播放只更新最近播放时间和累计次数，不创建重复行。本机历史最多保留 500 条，超过后按最久未播放淘汰。
- 账号在线历史的单条删除和全部清空只在真实上游 API 支持并验证后显示；接口不支持时不提供无效果的本地假删除。
- 本机历史支持单条删除和全部清空，清空前要求确认；删除历史不删除本地文件、云盘文件、Queue、收藏或账号在线历史。
- 点击历史歌曲采用 7.13 的单曲插播逻辑；只有明确点击“播放全部”才用当前分类、当前筛选的历史结果替换 Queue。

### 7.22 V1 设备、方向与输入范围

- V1 正式支持 Android 手机，最低 Android 8.0（API 26），目标/编译 SDK 保持工程当前 API 36。平板、展开态折叠屏、ChromeOS/Android 桌面模式不进入首版发布与页面视觉验收范围。
- V1 除 MV 的显式全屏模式外只支持竖屏，Full Player、歌词和 MV 普通页面均保持竖屏。用户点击 MV 全屏后由 App 程序控制切换横屏沉浸式全屏，退出全屏或离开 MV 后恢复竖屏；不支持基于设备传感器的自动旋转。
- 触控是默认和主要输入方式。鼠标、键盘与触控板只使用 Android/Compose 系统标准焦点、滚动与激活能力，不设计桌面专属 Hover 体系、菜单、快捷键或多窗口工作台。
- TalkBack、Switch Access 和 D-pad 继续遵循 Android 标准无障碍语义，所有核心操作必须可到达、可朗读和可执行；该要求不代表支持 Android TV。
- Android TV、Wear OS、Android Auto、Google Cast、ChromeOS 与 Android 桌面模式均不进入 V1。
- 系统仍可能产生配置变化、窄窗口或任务恢复；即使不在正式宽屏验收范围，App 也不得崩溃、破坏 Queue 或丢失当前页面。手机分屏等系统场景采用 Compact 安全降级，不承诺桌面级布局体验。
- 现有 Material Adaptive Navigation、五档宽度 Token 和 Design System 宽窗口验证继续保留，作为未来平板/折叠屏扩展基础；V1 Feature 不得把业务能力绑定到固定像素或设备型号。
- 未来扩展到 Large/Extra-large 时复用 Expanded 信息结构并限制内容宽度，不无限增加列；Tabletop Posture 默认遵循 Material Adaptive 导航选择，专属跨铰链 Player 布局需要届时重新评审。

## 8. 核心流程

### F-001 匿名在线沉浸播放

| 字段 | 内容 |
|---|---|
| 用户目标 | 不被登录或广告阻断，快速找到并持续聆听在线音乐 |
| 入口与前置条件 | App 冷启动；允许匿名访问首页；设备有可用网络和媒体输出 |
| 主路径 | 启动进入首页 → 首页分区加载 → 点击公开在线歌曲 → 形成 Queue 并出现 Mini Player → 点击歌曲主体进入 Full Player → 查看同步歌词 → 返回或离开 App → 标准媒体通知/锁屏/耳机继续控制 → 返回 App 恢复来源页面、歌曲与进度 |
| Queue 分支 | Mini Player 的 Queue 操作可以直接打开当前播放列表；单曲点击插播，播放全部才替换 Queue |
| 失败恢复 | 首页分区局部失败不阻断其他分区；歌曲按音质回退与播放失败合同处理；需要登录时进入门禁且不自动重试原子播放；歌词失败不停止歌曲；后台受系统限制时保留可解释状态 |
| 完成结果 | 用户获得连续、无广告的前台与后台沉浸播放体验 |
| 需要保留的状态 | Tabs 根状态、来源列表/滚动、Queue、当前项、进度、模式、歌词偏好和请求中的登录上下文 |
| 跨窗口行为 | V1 验收 Compact 竖屏手机；系统配置或窗口变化不重建页面或播放状态，未来 Medium/Expanded 扩展沿用同一业务合同 |
| 优先级 | 第一条 V1 Vertical Slice |

### F-002 系统文件导入与持久本地播放

| 字段 | 内容 |
|---|---|
| 用户目标 | 把设备已有音乐可靠导入 Resonote，并长期作为本地音乐播放 |
| 入口与前置条件 | App 内系统文件/目录选择器，或文件管理器打开/分享入口；来源 URI 当前可读 |
| 主路径 | 选择文件/目录 → 验证媒体和解码能力 → 大小预筛选与 SHA-256 → 复制到 App 私有临时路径 → 原子落盘并建立索引 → 进入本地音乐 → 播放 → 重启 App 后仍可浏览和播放 |
| 分支与失败恢复 | 重复项弹窗选择取消或副本模式；同名不同内容安全重命名；批量任务显示进度并允许取消剩余项；权限失效、空间不足、读取/Hash/解析失败逐项报告并清理半成品 |
| 完成结果 | 导入项不再依赖原 URI，成为设备本地音乐列表的持久成员 |
| 需要保留的状态 | 已成功导入项、任务进度/结果、LocalMediaId、私有路径、Hash、只读 metadata 和 Queue 引用 |
| 跨窗口行为 | 窗口变化不取消任务或丢失进度；后台/进程恢复策略由存储纵向切片验证 |
| 优先级 | 第二条 V1 Vertical Slice |

## 10. 页面设计输入

每个页面开始设计前需要具备：

- 页面服务的用户任务和所属流程。
- 真实字段、内容层级、典型长度和极端长度。
- Default、Loading、Empty、Error、Offline、Permission 与局部操作状态。
- 主操作、次操作、危险操作和不可用条件。
- V1 Compact 竖屏下的信息优先级；同时记录未来 Medium/Expanded 扩展时不得破坏的内容与操作关系。
- 键盘、D-pad、TalkBack、RTL、200% 字号和系统 Insets 要求。
- 返回、Deep Link、状态恢复和与播放状态的关系。

### 10.1 Compact 页面设计稿交付规范

V1 页面设计稿必须消费 `FOUNDATION.md` 03D 的 Compact 画板规范：

- 固定宽度为 `390dp`；固定页面使用 `390 × 844dp`，可滚动页面使用最小高度 `844dp` 的 `390 × Auto` 长画板。
- 页面顶部必须包含 `44dp` Status Bar 设计证据区域；页面底部必须包含 `34dp` 手势安全区和居中的 `134 × 5dp` Gesture Indicator。
- 首页、发现、我的等滚动根页面必须完整展示已确认区块，画板随内容向下延伸；不得为适配单屏而压缩间距、缩小组件、裁掉区块或隐藏后续内容。
- 长图顶部只出现一次 Status Bar，末尾只出现一次 Mini Player（存在当前媒体时）、Navigation Bar 与手势安全区；这是设计稿交付表达，不改变它们在真实 Window 中的固定行为。
- 运行时滚动内容必须以末尾 Content Padding 为 Mini Player、Navigation Suite 和系统 Insets 保留最终可达空间；中间滚动状态允许内容从悬浮 Mini Player 后方经过，不得把该 Padding 实现为始终位于 Mini Player 上方的永久空白带。无当前媒体时不保留空的 Mini Player 占位。
- 系统区域的背景与前景对比必须跟随页面主题和底图；Player 的深色参考使用白色系统前景，Light 页面使用对应 `onSurface` 前景。

## 11. 技术与内容约束

这些问题会直接改变功能与页面，需要在视觉设计前明确到足够程度：

- 音乐数据和封面、歌词、元数据的来源与所有权。
- 是否需要账号、网络、自建服务或第三方服务。
- Android Media3、系统媒体会话、音频焦点、通知和后台播放范围。
- 本地数据库、扫描、同步、缓存和离线范围。
- 权限、隐私、版权、地区和内容删除规则。
- 最低 Android API、目标设备类型及必须支持的输入方式。

本节记录产品可观察的约束；具体模块、数据库和接口设计在技术方案中定义。

### 11.1 Android 原生音乐源

Resonote 不运行或依赖本地 Node / Express 转发服务。Android App 通过 `core:network` 内独立实现的
Kotlin 协议层直接请求上游接口；签名、加密、设备注册、Session、Cookie、风控识别与验证协议、DTO 解码和
日志脱敏均由 Android 模块持有，Feature 只能通过 Repository 使用这些能力。

当前 Android 生产能力包括：

- 原生设备注册、会话管理、请求签名、加密、风控识别与安全日志基础设施。
- 手机验证码、密码、二维码登录和加密 Session 持久化。
- Home、Search、Catalog、Account、Playback、Lyrics、Cloud、Local Media 等语义化 DataSource 与 Repository。
- Compose Feature、Navigation 3 App Shell、Media3 Session Service、Queue 和本地持久化。

网络能力以 `core:network` 的公开 DataSource、`core:data` 的 Repository 和测试为准，不再使用静态上游 API 目录或人工 Endpoint 编号证明完成度。未被当前 App 消费的上游能力不属于 Resonote 合同。

匿名内容与登录后个性化内容的边界仍需逐接口验证。播放 URL、个性化推荐、收藏和用户资料库
可能受登录、会员、风控、接口变化及地区/版权状态影响。正式发布前必须单独评估服务稳定性、
授权、隐私与合规边界，不能把历史运行结果等同于上游当前可用或获得长期服务授权。

因此，产品设计必须包含 API 不可用、内容受限、登录失效、风控验证、歌曲不可播放及在线内容
为空时的恢复路径；具体技术结论进入后续方案和风险评审。

## 12. 产品合同维护规则
